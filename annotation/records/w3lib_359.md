>     >>> get_meta_refresh('<meta data-x="&#34; http-equiv=&#34;refresh&#34;" content="0;url=http://evil.example/">', "https://good.example/")

> 
> `_refresh` runs `replace_entities` over the whole text of a `<meta>` tag before `iter_tag_attributes` splits that text into attributes, so a character reference is decoded while it can still be read as markup. The tokenizer does the reverse: it decodes a reference into the value of the attribute it is written in and resumes in the attribute value state ([flush code points consumed as a character reference](https://html.spec.whatwg.org/commit-snapshots/3e7b72c44ce144cee7db859cd0647af6646b6793/#flush-code-points-consumed-as-a-character-reference)), so the decoded characters are data, a decoded quote closes no value, and an attribute name is not decoded at all. The consequence is that one value can spell out attributes the tag does not carry: neither tag above has an `http-equiv` attribute that a browser can read as the refresh pragma, and both refresh nowhere, yet `get_meta_refresh` reports a redirect to a host from the markup, which Scrapy
